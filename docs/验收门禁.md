# DormPool 验收门禁

> 版本：v1.0 · 分支：`proto`
> 配套文档：[阶段规划书](阶段规划书.md)、[技术点清单](../技术点清单.md)
> 本文定义"做完的判据"。每个门禁给出：**怎么跑、通过条件、要留什么证据**。
> 门禁不是建议，是阶段出口。红灯不许进下一阶段（见规划书第六节）。

## 第零节 · 通用约定

### 0.1 执行环境

| 项 | 值 |
|---|---|
| Shell | Windows：PowerShell（启动/环境变量）或 Git Bash（门禁自动化脚本）；Ubuntu：bash |
| 解释器 | `python` = Python 3.12.x |
| 工作目录 | 所有命令均在仓库根 `f:/dormpool/dormpool`（Windows）或对应路径（Ubuntu）执行，**不要**在子目录里执行 |
| 绑定地址 | 只允许 `127.0.0.1`。**任何 `0.0.0.0` 视为门禁失败** |
| 端口 | `MASTER_PORT=8000`（来自 `shared/contracts.py`） |
| 已装依赖 | `psutil`、`Pillow`、`pynvml`、`fastapi`、`uvicorn`、`requests`、`python-multipart`；**无 torch** |

> **Windows 说明**：手动启动 Master / Worker 时用 PowerShell（见下方 0.2 / 0.5）；含 heredoc、`$!`、后台 `&` 的门禁自动化脚本须在 Git Bash 下执行。

### 0.2 标准环境变量（每个门禁开头先执行一次）

**Windows（PowerShell）**

```powershell
cd f:\dormpool\dormpool
$env:MASTER_URL     = "http://127.0.0.1:8000"
$env:SHARD_SIZE     = "1"
$env:DORMPOOL_DATA  = "data"
$env:WORKER_DATA_ROOT = "data/worker_data"
```

**Ubuntu / Linux（bash）**

```bash
cd /path/to/dormpool/dormpool
export MASTER_URL=http://127.0.0.1:8000
export SHARD_SIZE=1            # 门禁里刻意用小分片，便于观察逐任务行为
export DORMPOOL_DATA=data
export WORKER_DATA_ROOT=data/worker_data
```

`SHARD_SIZE` 默认 3（生产默认），门禁里用 1 是为了让 task 数量 ≥ 图片数，从而能观察"每个 Worker 确实各领了不同的活"。两者都必须在实现里支持。

### 0.3 端口预检（每个需要起 Master 的门禁都先跑）

**Windows（PowerShell）**

```powershell
netstat -ano | findstr ":8000"
# 无输出 = 端口空闲
```

**Ubuntu / Linux（bash）**

```bash
netstat -ano | grep ':8000' || echo "PORT-FREE"
```

- **通过**：无输出（Windows）或输出 `PORT-FREE`（Linux），或输出里的 PID 就是你自己上一轮没杀干净的进程（先 `taskkill /PID <pid> /F`（Windows）或 `kill <pid>`（Linux））。
- **失败**：有别人的进程占着 8000。换端口前先确认不是自己遗留。

### 0.4 证据存放

每个门禁的证据写进：

```
docs/log/evidence/<gate_id>/<step>.txt      # 命令原文 + 真实 stdout/stderr
docs/log/evidence/<gate_id>/<step>.png      # Console 截图（G4/G6 需要）
```

每条证据文件的**第一行必须是命令原文**，第二行起是真实输出。禁止手写"预期输出"，必须是复制粘贴的真实结果。

### 0.5 起停模板

**起 Master**

Windows（PowerShell）：

```powershell
cd f:\dormpool\dormpool
$env:DORMPOOL_DATA  = "data"
$env:SHARD_SIZE     = "1"
Start-Process python -ArgumentList "-m uvicorn master.main:app --host 127.0.0.1 --port 8000" -RedirectStandardOutput "$env:TEMP\master.log" -NoNewWindow
Start-Sleep 3
curl -s http://127.0.0.1:8000/ping
```

Ubuntu / Linux（bash）：

```bash
cd /path/to/dormpool/dormpool
python -m uvicorn master.main:app --host 127.0.0.1 --port 8000 > /tmp/master.log 2>&1 &
sleep 3
curl -s http://127.0.0.1:8000/ping
```

> 禁止 `--reload`（会派生出第二个进程，见风险 R1）。

**起 Worker A / B**

Windows（PowerShell）：

```powershell
$env:MASTER_URL     = "http://127.0.0.1:8000"
$env:WORKER_ID      = "worker-A"
$env:WORKER_DATA    = "data/worker_data/worker-A"
$env:MAX_SLOTS      = "1"
Start-Process python -ArgumentList "worker/main.py --headless" -RedirectStandardOutput "$env:TEMP\worker-a.log" -NoNewWindow -PassThru | Select-Object -ExpandProperty Id | Out-File "$env:TEMP\worker-a.pid"
```

Ubuntu / Linux（bash）：

```bash
MASTER_URL=http://127.0.0.1:8000 \
WORKER_ID=worker-A WORKER_DATA=data/worker_data/worker-A MAX_SLOTS=1 \
python worker/main.py --headless > /tmp/worker-a.log 2>&1 &
echo $! > /tmp/worker-a.pid
```

**收工（每个门禁结束必须执行）**

Windows（PowerShell）：

```powershell
Stop-Process -Id (Get-Content "$env:TEMP\worker-a.pid") -Force -ErrorAction SilentlyContinue
Stop-Process -Id (Get-Content "$env:TEMP\worker-b.pid") -Force -ErrorAction SilentlyContinue
netstat -ano | findstr ":8000"   # 必须无输出
```

Ubuntu / Linux（bash）：

```bash
kill $(cat /tmp/worker-a.pid) 2>/dev/null; kill $(cat /tmp/worker-b.pid) 2>/dev/null
netstat -ano | grep ':8000'    # 必须为空
```

### 0.6 响应形状约定（门禁脚本依赖，先于实现锁定）

下面三条是 M1 必须交付的 JSON 形状。骨架现状与之有**三处偏差**，S2 起必须改正，否则 G2/G3/G5 的脚本直接跑不通：

1. `GET /workers` 现在返回**裸列表** `[entry, ...]`，且字段名是 `contrib`。要求改为
   `{"workers": [ ... ]}`，字段名统一为 **`contrib_state`**（与 `WorkerContribState`、`WorkerHeartbeat.contrib_state` 同名，避免两套叫法）。
2. `GET /workers` 的每个元素必须**包含能力字段**（`cpu_cores`/`ram_gb`/`gpu_name`/`gpu_vram_gb`/`max_slots`）。骨架的 `WorkerEntry.to_dict()` 只吐了状态，没吐能力——G2-4 的"真嗅探"断言因此缺少依据。
3. `GET /jobs/{job_id}` 必须附带 `tasks` 数组（`attempts` 嵌在 task 内），详见 G3。G3/G5 的全部唯一性与不双计断言都建立在这份数据上。

**`GET /workers` 目标形状**

```json
{
  "workers": [
    {
      "worker_id": "worker-A",
      "hostname": "DESKTOP-XXXX",
      "conn_state": "online",
      "contrib_state": "available",
      "exec_state": "idle",
      "free_slots": 1,
      "max_slots": 1,
      "running_task_ids": [],
      "cpu_cores": 8,
      "ram_gb": 31.83,
      "gpu_name": null,
      "gpu_vram_gb": null,
      "cpu_pct": 12.4,
      "gpu_pct": null,
      "last_seen": 1763000000.0
    }
  ]
}
```

> 这些都是在**既有路径上扩展响应字段**，不新增 API 路径，因此不需要动 `shared/contracts.py`（契约冻结不受影响）。但字段名一旦定了就不能改，G2–G6 的脚本会按名字取值。

## G0 · 契约冻结

**阶段**：S0 · **预估**：10 分钟 · **负责人**：全员（A 仲裁）

### 怎么跑

```bash
cd /f/dormpool/dormpool

# G0-1 契约可导入
python -c "import shared.contracts as c; print('contracts-ok')"

# G0-2 关键常量与枚举齐全且取值正确
python - <<'PY'
import shared.contracts as c
assert c.MASTER_PORT == 8000
assert c.HEARTBEAT_INTERVAL == 0.5
assert c.LEASE_DURATION == 120
assert c.LEASE_RENEW_BEFORE == 20
assert c.WORKER_TIMEOUT == 2.0
assert c.EXECUTOR_SUCCESS == 0 and c.EXECUTOR_TASK_FAIL == 1 and c.EXECUTOR_FATAL == 2
for e in ("JobStatus","TaskStatus","AttemptStatus","WorkerConnState",
          "WorkerContribState","WorkerExecState"):
    assert hasattr(c, e), e
assert c.JobStatus.COMPLETED.value == "completed"
print("constants-ok")
PY

# G0-3 每个模块都能 import 到共享类型，且不依赖 torch
python - <<'PY'
import importlib
mods = ["master.app.m1_api","master.app.m2_registry","master.app.m3_job",
        "master.app.m4_scheduler","master.app.m5_data","master.app.m6_metrics",
        "master.app.c3_validation",
        "worker.agent.w1_runtime","worker.agent.w2_connector","worker.agent.w3_monitor",
        "worker.agent.w4_contrib","worker.agent.w5_exec","worker.agent.w6_control",
        "executor.run","shared.contracts"]
bad = []
for m in mods:
    try: importlib.import_module(m)
    except Exception as e: bad.append((m, repr(e)))
print("imported", len(mods)-len(bad), "/", len(mods))
for m,e in bad: print("FAIL", m, e)
assert not bad
print("modules-ok")
PY

# G0-4 全仓禁用 torch
grep -rn "import torch\|from torch" --include=*.py . && echo "FAIL torch" || echo "no-torch-ok"

# G0-5 禁止 0.0.0.0 绑定：只查"真的会绑定"的位置——uvicorn 调用参数与代码里的 host 赋值，
#      不查文档字符串/注释（master/main.py 的 docstring 里那句示例是历史文本，不算违规）
grep -rn "\-\-host[ =]*0\.0\.0\.0\|host=[\"']0\.0\.0\.0" --include=*.py master worker executor shared \
  && echo "FAIL wildcard-bind" || echo "no-wildcard-bind-ok"

# G0-6 未实现的桩必须显式，不能靠"静默返回 None"骗过门禁
grep -rn "NotImplementedError\|status_code=501" --include=*.py master worker executor | wc -l
```

### 通过条件

| 子项 | 通过条件 |
|---|---|
| G0-1 | 打印 `contracts-ok`，无 `ImportError`/`SyntaxError` |
| G0-2 | 打印 `constants-ok`。任一断言失败 = 有人擅自改了冻结常量 |
| G0-3 | 打印 `imported 15 / 15` 与 `modules-ok`。允许模块内部是 `NotImplementedError` 的骨架，但 **import 不得失败** |
| G0-4 | 打印 `no-torch-ok` |
| G0-5 | 打印 `no-wildcard-bind-ok`。**注意**：`master/main.py` 顶部 docstring 里有一句 `--host 0.0.0.0` 的历史示例，它不构成绑定，因此 G0-5 只匹配真实调用参数；若你把 docstring 也改掉更好，但不是门禁要求 |
| G0-6 | 打印的数字是当前**已知未实现点**的行数，用于 S0 登记基线并随阶段推进**单调下降**；若某阶段结束后不降反升，说明有人新加了桩。S0 实测基线 **16**，构成：`m1_api.py` 12 处 `status_code=501`、`c3_validation.py` 1 处 `raise NotImplementedError`、`w2_connector.py` 1 处 `upload_output` 桩、`example_handler.py` 1 处模板桩、`w5_exec.py` 1 处 `except NotImplementedError`（这个是**捕获**不是桩，逻辑上应保留）。全绿时应剩约 **3** 行（抽象基类的 `raise`、异常捕获、以及保留的模板文件），不是 0 |

### 要留的证据

- `docs/log/evidence/G0/01-import.txt`、`02-constants.txt`、`03-modules.txt`、`04-grep.txt`
- 规划书 S0 的 9 条接口决策，三人分别在各自模块日志末尾写"已确认"。

### 常见红灯

| 现象 | 原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError: shared` | 在子目录执行，或用了 `python -I` | 回仓库根执行；不要加密 `-I`（会切断 cwd 的 sys.path） |
| 某个模块 import 就抛异常 | 有人把骨架写成了会执行的代码（如在模块顶层起线程） | 副作用必须挪进 `start()`/`main()` |
| `grep torch` 命中 | 有人照抄网上的 GPU 探测 | 改 `pynvml`，无则 `(None, None)`（风险 R5） |

## G1 · 单机计算

**阶段**：S1 · **预估**：40 分钟 · **负责人**：C

### 怎么跑

```bash
cd /f/dormpool/dormpool
mkdir -p /tmp/g1 && cd /tmp/g1

# G1-1 造输入：12 张确定性的测试图，打成一个平铺 zip
python - <<'PY'
import io, zipfile, random
from PIL import Image
random.seed(20260101)          # 固定种子 -> 可复现
with zipfile.ZipFile("input.zip","w",zipfile.ZIP_DEFLATED) as z:
    for i in range(12):
        im = Image.new("RGB", random.choice([(320,240),(200,300),(128,128),(512,64)]),
                       (i*17%256, i*53%256, i*97%256))
        px = im.load()
        for x in range(0, im.width, 5):
            for y in range(0, im.height, 5):
                px[x,y] = ((x*7)%256, (y*13)%256, (x*y)%256)
        b = io.BytesIO(); im.save(b, "PNG")
        z.writestr(f"img_{i:02d}.png", b.getvalue())
print("made input.zip")
PY

# G1-2 跑 executor，捕获退出码与末行 JSON
cd /f/dormpool/dormpool
python executor/run.py image_thumb /tmp/g1/input.zip /tmp/g1/out1.zip --worker-id c-test \
  > /tmp/g1/run1.stdout 2> /tmp/g1/run1.stderr
echo "EXIT=$?"
tail -n 1 /tmp/g1/run1.stdout

# G1-3 校验输出：manifest 结构 + 尺寸 + 哈希自洽
python - <<'PY'
import json, zipfile, hashlib
z = zipfile.ZipFile("/tmp/g1/out1.zip")
names = z.namelist()
assert "manifest.json" in names, names
manifest = json.loads(z.read("manifest.json"))
assert isinstance(manifest, list) and len(manifest) == 12, len(manifest)
keys = {"input_name","input_sha256","output_name","output_sha256","out_w","out_h"}
for r in manifest:
    assert set(r) == keys, r
    assert len(r["input_sha256"]) == 64 and len(r["output_sha256"]) == 64
    assert r["output_name"].startswith("thumbs/"), r
    assert 1 <= r["out_w"] <= 128 and 1 <= r["out_h"] <= 128, r
    data = z.read(r["output_name"])
    assert hashlib.sha256(data).hexdigest() == r["output_sha256"], r["output_name"]
print("manifest-ok", len(manifest))
PY

# G1-4 Master 侧权威 C3 校验器（与 G1-3 的 inline 检查是两条独立代码路径）
python - <<'PY'
from master.app.c3_validation import validate_result
n = validate_result("/tmp/g1/out1.zip", {"task_id":"t","task_type":"image_thumb","input_ref":"x"})
print("validated-units", n)
assert n == 12, n
PY

# G1-5 确定性：同输入重跑，输出字节必须完全一致
python executor/run.py image_thumb /tmp/g1/input.zip /tmp/g1/out2.zip --worker-id c-test > /dev/null 2>&1
sha256sum /tmp/g1/out1.zip /tmp/g1/out2.zip

# G1-6 换进程/换时区重跑，仍然一致（排除时间戳依赖）
TZ=Asia/Shanghai python executor/run.py image_thumb /tmp/g1/input.zip /tmp/g1/out3.zip > /dev/null 2>&1
sha256sum /tmp/g1/out3.zip

# G1-7 单机基准 P_i
python executor/benchmark.py --task-type image_thumb --input /tmp/g1/input.zip --repeat 3
```

### 通过条件

| 子项 | 通过条件 |
|---|---|
| G1-2 | `EXIT=0`；末行 stdout 是**合法 JSON** 且形如 `{"units_done": 12, "detail": "..."}` |
| G1-3 | `manifest-ok 12`：字段集合完全等于 6 个 key，无多余无缺失；每个 `output_sha256` 与归档内实际字节的 sha256 一致；`out_w/out_h` 均 ≤128 且 ≥1 |
| G1-4 | `validated-units 12`，且该校验器**不信任** executor 自报值——把 manifest 篡改一条后必须抛 `ValidationError`（追加检查见下） |
| G1-5 | 两行 sha256 **完全相同** |
| G1-6 | 第三行 sha256 与前两行**完全相同**（证明不依赖本机时区/时间） |
| G1-7 | 输出 JSON 含 `throughput` 字段，数值 >0，且 `units_done == total_tasks * 12` |

**G1-4 的篡改检查（必做，防"假校验器"）**

```bash
python - <<'PY'
import json, zipfile, shutil
src, dst = "/tmp/g1/out1.zip", "/tmp/g1/out1_tampered.zip"
with zipfile.ZipFile(src) as z:
    items = {n: z.read(n) for n in z.namelist()}
m = json.loads(items["manifest.json"]); m[0]["out_w"] = 999
items["manifest.json"] = json.dumps(m).encode()
with zipfile.ZipFile(dst, "w", zipfile.ZIP_DEFLATED) as z:
    for n, b in items.items(): z.writestr(n, b)
print("tampered written")
PY
python - <<'PY'
from master.app.c3_validation import validate_result, ValidationError
try:
    validate_result("/tmp/g1/out1_tampered.zip", {"task_type":"image_thumb"})
    print("FAIL: validator accepted tampered manifest")
except ValidationError as e:
    print("rejected-ok:", e)
PY
```

通过条件：打印以 `rejected-ok` 开头。若打印 `FAIL: ...`，说明校验器形同虚设，G4 的证据链也随之失效。

### 要留的证据

- `docs/log/evidence/G1/01-exec.txt`（含 `EXIT=0` 与末行 JSON）
- `docs/log/evidence/G1/02-manifest.txt`、`03-validate.txt`、`04-tamper.txt`
- `docs/log/evidence/G1/05-determinism.txt`（三行 sha256 并列，肉眼可见相同）
- `docs/log/evidence/G1/06-benchmark.txt`（真实 P_i，S5/G6 要引用）

### 常见红灯

| 现象 | 原因 | 处置 |
|---|---|---|
| 两次 sha256 不同 | 用了 `ZipFile.write()`（写入源文件 mtime）或 PNG 里带了时间 | 用 `ZipInfo(date_time=(1980,1,1,0,0,0))` + `writestr`；PNG 保存不写 `tIME`/EXIF（风险 R2） |
| `unit_done` 数量对但尺寸不对 | `thumbnail()` 只缩不放，小图保持原尺寸 | 这是正确行为，不要在 gate 里写死 128；按 manifest 实际值断言 |
| manifest 顺序每次不同 | 按 `os.listdir`/zip 内顺序遍历 | 统一 `sorted(z.namelist())` |
| 校验器永远通过 | 只比较条数，没重算 sha256 | 见篡改检查；校验器必须重算至少 `output_sha256` 与尺寸 |

```bash
cd /f/dormpool/dormpool

import sys,json

for i in $(seq 1 12); do

      | python -c "import sys,json;d=json.load(sys.stdin);w=[x for x in d['workers'] if x['worker_id']=='worker-A'];print(w[0]['conn_state'] if w else 'MISSING')")

done
```

### 通过条件

## G5 · 动态自治

**阶段**：S5 · **预估**：60 分钟 · **负责人**：A（M2/M4）+ B（W4/W6）

### 前置条件（不满足则本门禁不可测）

- `executor` 支持 `DORMPOOL_EXECUTOR_DELAY_MS`（默认 0）：在处理**每张图之后** sleep 指定毫秒。它只影响耗时，**不得影响输出字节**。
  - 用途：让单个 shard 的执行时间足够长，从而能观察到 DRAINING、能在任务执行中途杀掉 worker。
  - 反身检查：G1-5 的确定性在 `DORMPOOL_EXECUTOR_DELAY_MS=50` 下重跑一次，sha256 必须与不设延时完全相同。
- Worker 支持 `--headless`，且暂停/恢复可由一个本地控制通道触发（stdin 行命令 `pause` / `resume`，或 `--control-file` 监听文件变化）。G5 用 stdin 行命令，因为最省事：

```bash
# 起 worker 时不要重定向 stdin，或用一个 FIFO/文件喂命令
```

### 怎么跑

**准备**：一份 12 张图的输入，`SHARD_SIZE=1`，`DORMPOOL_EXECUTOR_DELAY_MS=800`，`MAX_SLOTS=1`。这样每个 task 约 1 秒以上，12 个 task 有足够时间窗口做动作。

#### G5-A 暂停：停止领取、在跑的跑完（DRAINING → PAUSED）

```bash
cd /f/dormpool/dormpool
export SHARD_SIZE=1 DORMPOOL_EXECUTOR_DELAY_MS=800

# 只起 worker-A，提交 12 图 Job
# ...（同 G3-2，把 7 换成 12）

# 等 A 开始干活（看到 1 个 running task）
for i in $(seq 1 20); do
  S=$(curl -s http://127.0.0.1:8000/workers \
      | python -c "import sys,json;w=[x for x in json.load(sys.stdin)['workers'] if x['worker_id']=='worker-A'];print(w[0]['exec_state'],w[0]['contrib_state'])")
  echo "t=$((i))s $S"; case "$S" in busy*) break;; esac; sleep 1
done

# 发 pause，然后连续采样
echo pause > /tmp/worker-A.stdin
for i in $(seq 1 20); do
  curl -s http://127.0.0.1:8000/workers \
    | python -c "import sys,json;w=[x for x in json.load(sys.stdin)['workers'] if x['worker_id']=='worker-A'][0];print(w['contrib_state'],w['exec_state'],w['free_slots'])"
  sleep 1
done
```

**通过条件（G5-A）**

1. pause 后，`contrib_state` 在一个 `HEARTBEAT_INTERVAL`（10s，允许多一个周期）内变 `draining`，**此时 `exec_state` 仍为 `busy`**——证明在跑的任务没被中断。
2. 该任务完成后（`exec_state` 变 `idle`），`contrib_state` 变 `paused`。**顺序必须是 draining → paused，不能直接跳 paused。**
3. 从 pause 到 `paused` 期间，`done_tasks` **最多再涨 1**（只有那个在跑的 task 收尾）——证明"停了新领取，但没杀在跑的"。
4. `free_slots` 在 `paused` 之后为 0。

#### G5-B 恢复：重新开始领取

```bash
echo resume > /tmp/worker-A.stdin
sleep 12
curl -s http://127.0.0.1:8000/workers \
  | python -c "import sys,json;w=[x for x in json.load(sys.stdin)['workers'] if x['worker_id']=='worker-A'][0];print(w['contrib_state'],w['exec_state'])"
# 继续轮询 job，done_tasks 必须继续增长
```

**通过条件（G5-B）**：`contrib_state` 回到 `available`；此后 30s 内 `done_tasks` 较 pause 结束时**增加 ≥1**。

#### G5-C 热加入：中途加入的节点分到剩余工作

```bash
# 在 A 还在跑、Job 尚未完成时，起 worker-B
MASTER_URL=http://127.0.0.1:8000 \
WORKER_ID=worker-B WORKER_DATA=data/worker_data/worker-B MAX_SLOTS=1 \
python worker/main.py --headless > /tmp/worker-B.log 2>&1 &
echo $! > /tmp/worker-B.pid

# 记录加入时刻的 done_tasks，等完成
```

**通过条件（G5-C）**

1. `worker-B` 在 `WORKER_TIMEOUT` 内出现在 `/workers`，状态 `online/available/idle`。
2. Job 完成时，`worker-B` 有 **≥1** 条 `succeeded` attempt，且其 `units_done > 0`。
3. `worker-B` 首次 claim 发生在它注册**之后**（日志时序可查），不会领到在它加入前就已分配给 A 的任务。
4. 若 Job 在 B 加入前已完成，本子项**判为不可测**（不是通过）：必须重跑，确保 B 在 `done_tasks < total_tasks` 时加入。

#### G5-D 杀进程：任务被回收并由另一台完成，且不双计

```bash
# 新 Job（12 图，SHARD_SIZE=1），A、B 都在线
# 等两边都有任务在跑，然后硬杀 A
kill -9 $(cat /tmp/worker-A.pid)
echo "killed A at $(date +%s)"

# 轮询 job 直到 completed 或 failed（最多 5 分钟）
```

**通过条件（G5-D）**

1. A 被杀后 ≤ `WORKER_TIMEOUT`+扫描余量（≤45s），`/workers` 中 A 变 `offline`，`free_slots=0`。
2. A 手上未完成的 task 在 `LEASE_DURATION=120`s 内（通常是失联判定后立即）回到 `retry_pending`，随后被 B 领取并 `succeeded`。Job 最终 `completed`。
3. **不双计**：`SUM(所有 succeeded attempt 的 units_done) == 提交图片总数`（=12）。A 被中断的那条 attempt 状态为 `expired`/`failed`，`units_done == 0`，不计入。
4. 最终 `result.zip` 的 manifest 仍有 12 条，无重复 `input_name`。
5. 若 A 在被杀前已把某 task 上传成功但还没来得及 commit，该迟到结果不得造成第二个 succeeded attempt；Master 必须返回 `discarded`（技术点 I4）。

### 常见红灯

| 现象 | 原因 | 处置 |
|---|---|---|
| pause 后直接 `paused`，没有 `draining` | `state()` 只看"是否手动暂停" | 先看 `busy_slots() > 0` 再返回 DRAINING |
| pause 后 Master 还在派活 | 只在本地不领，但 Master 仍按旧状态预分配 | 派任务前读 peer 的 `contrib_state`，或让 claim 返回空 |

| 全流程 2 秒就结束了，来不及做动作 | 没开 `DORMPOOL_EXECUTOR_DELAY_MS`，或 `SHARD_SIZE` 太大 | 按前置条件设置延时与小分片 |

### 常见红灯

| 现象 | 原因 | 处置 |
|---|---|---|
| `eta_pool_pct` 恒为 `100.0`、`speedup_S` 恒等于 2 | `p_pool = sum(per_dev)`（骨架现状） | 重写 `summary()`：P_pool 用池化墙钟，P_i 用单机基准（风险 R7） |
| `eta_pool_pct > 110` | 分母用了单台 P_i 或窗口不一致 | ΣP_i 必须包含所有参与设备；P_pool 窗口与 P_i 窗口同口径 |
| 数字随刷新剧烈跳动 | 吞吐按"最近 N 秒"滑动，但 N 太小 | 固定测量窗口，或对同一 Job 用 `created_at→finished_at` 定格计算 |
| 失败 attempt 被计入 | 在 `assign/commit` 入口就写 MetricRecord | 只在**成功**分支写，且同一 attempt 只写一次（技术点 J1） |
| `per_device_throughput` 出现 `unknown` | Worker 未带 `worker_id` 上报 | 未注册的 worker 拒绝 commit |
