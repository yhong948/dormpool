# 局域网双机部署操作手册

> 适用：一台 Master 主机 + 一台或多台局域网内的 Worker 机器。
> 前提：两台机器都能运行 Python 3.12 并装好 `requirements.txt`。

---

## 一句话回答三个问题

| 问题 | 答案 |
|------|------|
| 要开防火墙端口吗 | **只在 Master 机器上**开 **TCP 8000 入站**（限制为"专用网络"）。Worker 机器**不开放任何端口** |
| 要配 IP 吗 | 不用改网络配置。只需：Master 绑定自己的局域网 IP，Worker 的 `MASTER_URL` 指向那个 IP |
| 要改代码吗 | 不用。Master 已支持 `--host` / `MASTER_BIND` |

---

## 步骤 0 · 确认 Master 机器的局域网 IP

在 **Master 机器**上：

```bash
ipconfig
# 找 "IPv4 地址" 那一行，例如 10.4.139.66
```

注意区分：

- `127.0.0.1` —— 只有本机能访问，**局域网其他机器连不上**
- `169.254.x.x` —— 自动私有地址，说明没拿到 DHCP，网络本身有问题
- `10.x.x.x` / `192.168.x.x` / `172.16–31.x.x` —— 正常的局域网地址

> 建议给 Master 机器在路由器上做 **DHCP 地址保留**（或设固定 IP）。否则 IP 一变，所有 Worker 都要改配置。

---

## 步骤 1 · 在 Master 机器上开防火墙入站规则

以 **管理员身份** 打开 PowerShell，执行：

```powershell
New-NetFirewallRule `
  -DisplayName "DormPool Master 8000" `
  -Direction Inbound `
  -Protocol TCP `
  -LocalPort 8000 `
  -Action Allow `
  -Profile Private
```

要点：

- `-Profile Private` **只对"专用网络"生效**。连的是家庭/办公 Wi-Fi 时通常是专用网络；如果当前网络被识别为"公用网络"，Windows 不会应用这条规则（这是有意的保护，不要在公用网络上开放）。
- 检查当前网络类型：`Get-NetConnectionProfile`
- 只想临时开放，收工后可删除规则：

```powershell
Remove-NetFirewallRule -DisplayName "DormPool Master 8000"
```

- 如果开了第三方防火墙（360、火绒等），需要在它自己的界面里放行 **TCP 8000**，Windows 规则不生效。

## 步骤 2 · 启动 Master（绑定局域网 IP）

在 **Master 机器**上：

```bash
cd f:/dormpool/dormpool
export DORMPOOL_DATA=data
export SHARD_SIZE=3

python -m uvicorn master.main:app --host 10.4.139.66 --port 8000
```

**必须显式写 `--host <局域网IP>`**，不能省略：

- 省略时 uvicorn 默认绑 `127.0.0.1`，局域网访问会连接被拒
- **不要用 `0.0.0.0`**。代码会拒绝这个值（它会暴露到所有网卡，包括公网口），门禁 G0-5 也把它判为失败

也可以走程序入口，效果相同：

```bash
MASTER_BIND=10.4.139.66 python master/main.py
```

### 启动后自检（在 Master 机器上）

```bash
netstat -ano | grep ':8000' | grep LISTENING
```

正确的输出形如 —— 监听地址是具体 IP，不是 `0.0.0.0`：

```
TCP    10.4.139.66:8000    0.0.0.0:0    LISTENING    28052
```

然后本机测一次局域网地址（不是 loopback）：

```bash
curl http://10.4.139.66:8000/ping
# {"ok":true,"ts":...}
```

## 步骤 3 · 在另一台机器上验证连通

先不要启动 Worker，先确认网络通：

```bash
# 另一台机器上执行
curl http://10.4.139.66:8000/ping
```

按结果排查：

| 现象 | 原因 | 处置 |
|------|------|------|
| `{"ok":true,...}` | 通 | 继续下一步 |
| 连接超时 | 防火墙没放行，或网络类型是"公用" | 回到步骤 1；确认 `Get-NetConnectionProfile` 是 Private |
| 连接被拒绝（Connection refused） | Master 没起，或绑的是 127.0.0.1 | 检查 `netstat` 的监听地址 |
| 找不到主机 | 两台机器不在同一网段 | `ipconfig` 对比子网掩码；确认没连错 Wi-Fi |
| 有响应但很慢 | 走了 VPN/代理 | 临时关闭代理，或给局域网地址加直连规则 |

## 步骤 4 · 在另一台机器上启动 Worker

```bash
# 1. 拷贝或克隆整个仓库（Worker 需要 executor/ 和 shared/）
cd /path/to/dormpool

# 2. 安装依赖
pip install -r requirements.txt

# 3. 启动
export MASTER_URL=http://10.4.139.66:8000
export WORKER_ID=worker-B            # 每台必须不同
export WORKER_DATA=data/worker-B     # 每台必须不同
export MAX_SLOTS=1

python worker/main.py --headless
```

要点：

- **`WORKER_ID` 每台不同**，否则会被当成同一节点的重连，互相顶掉
- **`WORKER_DATA` 每台不同**，避免本地文件互相覆盖
- Worker **不需要开放任何端口**，它只主动出站连 Master
- 日志里应看到注册成功，并显示这台机器的真实硬件：

```
[w2] Registered worker_id=worker-B cpu=8 ram=15.7GB gpu=NVIDIA GeForce GTX 1650 score=1|...
```

## 步骤 5 · 验证双机真的都在池子里

在任意能访问 Master 的机器上：

```bash
curl http://10.4.139.66:8000/workers
```

应该看到两条记录，`conn_state` 都是 `online`，且 `cpu_cores` / `gpu_name` 与各自机器相符 —— 这是判断"嗅探到了真实硬件"还是"配置写错了"的关键依据。

浏览器打开：

```
http://10.4.139.66:8000/console
```

打开页面后，节点表里应出现两台机器。

## 步骤 6 · 跑一次真实双机任务

保持 `SHARD_SIZE=1`（每张图一个任务），这样任务数足够多，能明显看到两台机器分担：

```bash
JOB=$(curl -s -X POST http://10.4.139.66:8000/jobs \
  -F "task_type=image_thumb" -F "file=@你的图片.zip" \
  | python -c "import sys,json;print(json.load(sys.stdin)['job_id'])")
echo $JOB
```

轮询进度：

```bash
curl -s \
  http://10.4.139.66:8000/jobs/$JOB \
  | python -c "import sys,json;d=json.load(sys.stdin);print(d['status'],d['done_tasks'],'/',d['total_tasks'])"
```

确认两台都出了力（每个任务的 attempt 里记录了 worker_id）：

```bash
curl -s \
  http://10.4.139.66:8000/jobs/$JOB \
  | python -c "
import sys,json
d=json.load(sys.stdin)
w=set()
for t in d['tasks']:
    for a in t.get('attempts',[]):
        if a['status']=='succeeded': w.add(a['worker_id'])
print('workers that did work:', sorted(w))
"
```

期望输出包含两个 worker_id。只有一台的话，检查另一台的 `MAX_SLOTS` 和日志里有没有 claim。

## 双机实测要记录的数据（对应评分表的"有效算力聚合"）

现在有了真实的两台机器，可以按题目要求做**独立单机**与**池化**两次测量：

1. **单机基准 P_i**：停掉 B，只留 A，用同一份输入跑一次，记录 `units / wall`；再反过来测 B。
2. **池化 P_pool**：A、B 都在线，同一份输入跑一次，记录 `units / wall`。

```bash
curl -s \
  http://10.4.139.66:8000/metrics/summary | python -m json.tool
```

回代公式：

```
η_pool = P_pool / (P_A + P_B) × 100%
S      = P_pool / max(P_A, P_B)
```

**这次是真的跨物理机了**，可以据此给出真实聚合效率；之前同机双进程的数字不能用于对外宣称加速比。

## 常见问题

| 现象 | 原因 | 处置 |
|------|------|------|
| 另一台机器 `curl` 超时 | 防火墙 / 网络类型为公用 | 步骤 1；`-Profile Private` 且确认网络是专用 |
| Master 启动报"拒绝 0.0.0.0" | 代码主动拒绝通配绑定 | 改成具体的局域网 IP |
| `/workers` 只有一条 | 两台用了同一个 `WORKER_ID` | 改成不同值并重启 |
| Worker 起来但从不领任务 | `MAX_SLOTS` 为 0，或被 pause | 看 `contrib_state`；`MAX_SLOTS` 至少 1 |
| 任务都落到一台机器 | 另一台的 `free_slots` 长期 0 | 看它日志里有没有异常退出；检查 `WORKER_DATA` 是否可写 |
| 结果下载 404 | Job 未完成，或聚合失败 | 先查 Job 状态；`data/outputs/<job_id>/` 下是否有 `result.zip` |

## 安全边界（局域网演示时同样适用）

- 只在**受信任的局域网**上开端口；不要把 8000 映射到公网
- 防火墙规则限定 `-Profile Private`，不要在公用网络上开放
- Master 只绑定具体 LAN IP，不绑通配地址
- 每个设备所有者有权随时 `pause`，这是设计里明确的控制边界
