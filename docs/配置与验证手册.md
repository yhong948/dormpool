# 第一部分 · 配置

## 1.0 配置全景

```
                    ┌─────────────────────────────┐
                    │  Master（一台机器）          │
                    │  MASTER_BIND  监听地址       │
                    │  MASTER_PORT  监听端口       │
                    │  DORMPOOL_DATA   数据根目录  │
                    │  SHARD_SIZE      切分粒度    │
                    └──────────────┬──────────────┘
                                   │ Worker 主动出站连接（无需开放端口）
                    ┌──────────────┴──────────────┐
        ┌───────────▼──────────┐   ┌─────────────▼────────┐
        │ Worker A             │   │ Worker B             │
        │ MASTER_URL           │   │ MASTER_URL           │
        │ WORKER_ID    各不相同 │   │ WORKER_ID            │
        │ WORKER_DATA  各不相同 │   │ WORKER_DATA          │
        │ MAX_SLOTS            │   │ MAX_SLOTS            │
        └──────────────────────┘   └──────────────────────┘
```

标记"各不相同"的两项**必须每台不同**，其余应保持一致。

## 1.1 Master 配置

| 变量 | 默认 | 作用 | 配错的后果 |
|------|------|------|-----------|
| `MASTER_BIND` | `127.0.0.1` | 监听地址。**只在 `python master/main.py` 入口生效** | 填 `0.0.0.0` 会启动即退出（故意拒绝） |
| `MASTER_PORT` | `8000` | 监听端口。**只在 `python master/main.py` 入口生效** | 端口被占用则启动失败 |
| `DORMPOOL_DATA` | `data` | 上传、分片、结果、输出的根目录 | 指向不存在的盘符 → 提交任务时 500 |
| `SHARD_SIZE` | `3` | 每个 Task 处理几张图 | 过大 → 任务少、负载不均、暂停响应慢；过小 → 调度开销占比高 |

### 关于 `--host` 与 `MASTER_BIND` 的坑

用 `python -m uvicorn` 启动时**不会**执行 `master/main.py` 里的 `if __name__ == "__main__"` 块，因此 `MASTER_BIND` / `MASTER_PORT` **不生效**，uvicorn 用自己的默认值（`127.0.0.1:8000`）。

| 启动方式 | 怎么指定地址 |
|---------|-------------|
| `python -m uvicorn master.main:app --host 10.4.139.66 --port 8000` | 用 `--host` / `--port` 参数，环境变量无效 |
| `MASTER_BIND=10.4.139.66 python master/main.py` | 用环境变量 |

两种方式都不要加 `--reload`：它会 fork 第二个进程，两个调度器争抢同一份内存状态。

### 通配符绑定会被拒绝

```bash
$ MASTER_BIND=0.0.0.0 python master/main.py
MASTER_BIND must be a specific address (e.g. 192.168.1.20), not '0.0.0.0':
a wildcard bind exposes the pool on every interface.
```

这是有意的：`0.0.0.0` 会把服务暴露到所有网卡（含公网口），门禁 G0-5 也判为失败。指定团队成员真正需要访问的那一个地址。

## 1.2 Worker 配置

| 变量 | 默认 | 作用 | 配错的后果 |
|------|------|------|-----------|
| `MASTER_URL` | `http://127.0.0.1:8000` | Master 地址 | 写成 `0.0.0.0` 无法连接；跨机时写 `127.0.0.1` 会连到自己 |
| `WORKER_ID` | 主机名 + 6 位 uuid | 节点身份 | **两台重复 → 互相顶掉**，池里只剩一个节点 |
| `WORKER_DATA` | `worker_data` | 本地工作目录 | **两台相同 → 分片/结果文件互相覆盖** |
| `MAX_SLOTS` | `2` | 并发任务上限 | `0` → 永不领取任务 |
| `WORKER_CONTROL_PORT` | `0`（关闭） | 开启后在本机端口提供 `/status` `/pause` `/resume` | 端口被占用时只告警不崩溃，控制面静默失效 |
| `WORKER_NO_REPL` | `0` | `1` 跳过交互式 REPL | 非终端环境（服务/计划任务）不设 `1` → 启动即退出 |
| `DORMPOOL_EXECUTOR_DELAY_MS` | `0` | 每张图后额外 sleep | 生产别设；只在演示"暂停/热加入"时用来拉长时间窗口 |

### 命令行参数（优先于环境变量）

```bash
python worker/main.py [--headless] [--master URL] [--worker-id ID] \
                      [--max-slots N] [--control-port P]
```

| 参数 | 等价环境变量 |
|------|-------------|
| `--headless` | `WORKER_NO_REPL=1` |
| `--master` | `MASTER_URL` |
| `--worker-id` | `WORKER_ID` |
| `--max-slots` | `MAX_SLOTS` |
| `--control-port` | `WORKER_CONTROL_PORT` |

### `MAX_SLOTS` 怎么选

| 场景 | 建议值 | 理由 |
|------|--------|------|
| 演示/多机验证，要看两台分担 | `1` | 每个节点一次一个任务，任务分布最清晰 |
| 日常贡献、机器较强 | `2`–`4` | 提高吞吐，但不要超过物理核数的一半 |
| 机器同时在跑别的工作 | `1` | 降低对前台影响 |

`MAX_SLOTS=1` 时，节点空闲后立刻领取下一个任务；不会因为并发为 1 而空转。

## 1.5 配置一致性检查表

起服务前对照一遍，这五项覆盖了绝大多数"跑不起来"：

| # | 检查 | 错了两台会怎样 |
|---|------|---------------|
| 2 | 每台 Worker 的 `WORKER_ID` 不同 | 池里只剩一个节点，另一个被顶掉 |
| 3 | 每台 Worker 的 `WORKER_DATA` 不同 | 分片/结果文件互相覆盖，结果错乱 |
| 4 | `MASTER_URL` 指到 Master 的**实际可达**地址 | 连接被拒或超时 |
| 5 | Master 用 `--host <LAN IP>` 而非默认值 | 局域网连接被拒 |

## L4 · 双机实测（真实性能数据）

同机双进程**不能**用来对外宣称加速比。有了两台物理机后按下面做，两组数据必须独立测量。

### 4.1 单机基准（逐台）

```bash
# 只保留 worker-A（停掉 B）
# 用同一份输入、同一 SHARD_SIZE、同一 delay
JOB1=$(curl -s -X POST http://<master-ip>:8000/jobs \
  -F "task_type=image_thumb" -F "file=@input.zip" \
  | python -c "import sys,json;print(json.load(sys.stdin)['job_id'])")

curl -s http://<master-ip>:8000/jobs/$JOB1 \
| python -c "
import sys,json
d=json.load(sys.stdin)
u=sum(a['units_done'] for t in d['tasks'] for a in t['attempts'] if a['status']=='succeeded')
w=d['finished_at']-d['created_at']
print('A: units',u,'wall',round(w,2),'P_A',round(u/w,4))
"
```

交换角色，只留 worker-B，得到 `P_B`。

### 4.2 池化

两台都在线，同一份输入再跑一次：

```bash
# 同样命令，记 units / wall → P_pool
```

### 4.3 计算并回代

```
η_pool = P_pool / (P_A + P_B) × 100%
S      = P_pool / max(P_A, P_B)
```

与接口值核对：

```bash
curl -s http://<master-ip>:8000/metrics/summary | python -m json.tool
```

| 字段 | 含义 | 一致性要求 |
|------|------|-----------|
| `p_pool` | 池化墙钟吞吐 | 与手算 `P_pool` 相差 <15% |
| `p_pool_source` | 必须为 `pool_wall_clock` | 否则指标不可信 |
| `per_device_throughput` | 各机器吞吐 | key 只能是真实出过力的机器 |
| `eta_pool_pct` | 聚合效率 | 落在 (0, 115] |
| `speedup_S` | 加速比 | 两机时应 >1 且 ≤2.05 |
| `total_records` | 成功 attempt 数 | 等于成功任务数，不含失败/被杀的 |

## 附 A · 故障速查

| 现象 | 最可能原因 | 检查命令 |
|------|-----------|---------|
| 池里只有一个节点 | `WORKER_ID` 重复 | `/workers` 里的 id 列表 |
| 局域网连不上 | Master 绑了 127.0.0.1 / 防火墙 | `netstat -ano \| grep :8000` 看监听地址 |
| Master 启动即退出，提示 wildcard | `MASTER_BIND=0.0.0.0` | 改成具体 LAN IP |
| Agent 起来就退出 | 非终端环境下 REPL EOF | 加 `--headless` |
| 结果上传 422 | 请求头把 multipart 覆盖成 JSON | 已修复；若复现查 `w2_connector` 是否在 Session 上设了全局 `Content-Type` |
| 暂停后 Master 仍派活 | 心跳滞后 | 应 ≤1 个心跳周期；查 `pause()` 后是否立即补发心跳 |
| 暂停后 `free_slots` 仍为 1 | 上报逻辑没按状态归零 | 已修复；非 `available` 应上报 0 |
| 杀节点 50 秒才判离线 | 扫描间隔过长 | 应为 `min(WORKER_TIMEOUT/4, 10)` |
| `gpu_name` 是 `"None"` 字符串 | 序列化时 `str(None)` | 应保持 `Optional[str]` → JSON `null` |
| Job 永远 `running` | 任务卡在 `retry_pending` 无人领 | 看是否有节点 available；看任务 `retry_count` |
| 下载 404 | 未完成或聚合失败 | `data/outputs/<job_id>/result.zip` 是否存在 |
| 任务全落一台机器 | 另一台 `free_slots` 长期 0 或被暂停 | `/workers` 看 `contrib_state` |
